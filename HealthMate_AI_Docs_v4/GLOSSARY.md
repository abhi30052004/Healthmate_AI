# Glossary

| Term | Meaning |
|---|---|
| Active profile | The health profile currently selected in the UI; backend still checks permission per request |
| AI usage quota | Limit on model operations or spend per user/global period |
| Audit event | Minimal record of a sensitive action and its outcome |
| Caregiver | A user granted specific access to another person's profile |
| Canonical test name | Normalised label used to group equivalent test names |
| Citation | Reference to a retrieved source record/document chunk |
| Clinician guest | Read-only viewer using a scoped share |
| Consent | Recorded permission for a specific purpose, such as caregiver access or sharing |
| Data provenance | Where a fact came from, when it was recorded and whether it was verified |
| Extraction candidate | OCR/AI-proposed field awaiting human review |
| MCP | Model Context Protocol; a standard interface for exposing scoped tools/resources to AI clients |
| PHI | Protected/personal health information; use the applicable legal definition for the jurisdiction |
| Profile isolation | Guarantee that users cannot access records outside their granted profile scope |
| RAG | Retrieval-augmented generation; retrieve evidence before generating an answer |
| Reference range | Range printed or supplied by a laboratory for a particular test/context |
| Share token | Opaque secret used to access a time-limited shared view |
| Synthetic data | Artificial records that do not describe a real person |
| Unverified | Extracted or entered information not yet confirmed under the product's verification workflow |
| Visit Pack | User-selected summary of relevant history for a clinician appointment |
